# 评测说明（指标口径与结果展示）

> 面向第三次汇报的"基础评测情况"页。**指标定义在前，展示口径在后**，
> 保证换模型、换批次时数字可比。

---

## 一、评什么

| 项 | 取值 | 理由 |
|---|---|---|
| 任务 | 四选一单项选择 | 答案唯一，判分可全自动，不需要人来当裁判 |
| 输入 | 题干 + 四个选项（纯文本） | 与数据集 `core` 子集一致；公式以 `^`/`_` 记号保留 |
| 输出要求 | 末尾单独一行「答案：X」 | 便于正则抽取；同时允许模型先写推理 |
| 参考标准 | 数据集 `answer` 字段（A–D） | 与站点公开答案一致，逐题可溯源 |

不评测：多选、填空、解答题；不评测解题过程质量；不做人工二次判卷。

---

## 二、两种测试方式（提示词固定）

同一个模型跑两遍，只有提示词不同，用来区分"会不会做"与"想清楚了没有"。

| 方式 | 参数 | 提示词 | 调用次数 | 适用 |
|---|---|---|---|---|
| **常规测试** | `--mode normal` | 一次性作答，允许简要说明，最后一行给答案 | 1 | 模拟考试场景、比模型基础能力 |
| **深度思考测试** | `--mode deep` | 固定五步：列条件 → 两种方法求解 → 回代验算 → 不一致就定位错步 → 给答案；随后进入固定复核轮，独立重算、纠错 | 默认 2（首答 + 1 轮复核），可用 `--deep-rounds N` 加到 3、4 | 观察"多想一会儿"能涨多少分、代价多大 |

固定提示词写在 `eval/prompts.py` 里（`NORMAL_*` / `DEEP_*` / `VERIFY_*`），不通过配置拼接——
**换提示词就等于换实验**，两次结果不可比，所以锁死。

判分只看最后一轮**有效**的「答案：X」；若末轮调用失败或为空，回退到上一轮并记 `fallback_stage`。
每轮抽取结果记在 `stage_answers`，summary 另给「多轮改判」统计（改判率、改对、改错）——
**复核轮不把上一轮答案写进提示词**，否则提升主要来自锚定而非独立验证。
`deep` 的 `max_tokens` 默认抬到 1024，避免推理被截断。

最终输出的正确率：

```
总体准确率 = 判对题数 / 参与评测题数
```

另附 95% 置信区间、六板块宏平均、板块×难度矩阵、未抽取率、平均调用次数与耗时、
token 消耗（输入/输出/每题）、截断条数。
同一模型两种方式的差值（deep − normal）就是"深度思考"的净收益，成本差看 `avg_calls` 与 token。

## 三、指标

### 2.1 主指标：准确率

```
Accuracy = 判对题数 / 参与评测题数
```

- **判对**：抽取到的选项字母与 `answer` 完全相等；
- 抽取不到答案记为**未抽取**（invalid），计入分母、判错——这是模型的真实失败，不能从分母里剔掉；
- 调用失败（超时 / 5xx / 连接拒绝）单独记 `error`，同样计入分母判错，另报 `error_rate`；
  若 `error_rate > 5%`，这次结果不可用，应排查后再跑。

### 2.2 置信区间

1,000 题上 1 个百分点 ≈ 10 道题。两个模型差 2 个点，很可能只是抽样波动，
因此每个准确率都配 **Wilson 95% 置信区间**。汇报时的写法：

> 模型 A 68.4% [65.5%, 71.2%]，模型 B 66.9% [64.0%, 69.8%] —— 区间大幅重叠，差距不显著。

### 2.3 辅助指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 六板块宏平均 | 六个板块准确率取等权平均 | 板块已均衡，仍可用它防止单板块波动主导结论 |
| 未抽取率 | 没抽出 A–D 的比例 | 反映指令遵循能力；高说明模型不按格式答 |
| 调用失败率 | 请求层失败比例 | 判定本次结果是否可用 |
| 平均单题耗时 | 端到端秒数 | 成本/部署可行性 |
| 选项分布 | 预测 A/B/C/D 的频次 | 全押一个字母会在这里暴露 |
| 抽取方式分布 | 答案标记 / boxed / 兜底扫描…… | 兜底占比高说明输出不规范 |

### 2.4 两条"下限"参照

| 参照 | 准确率 | 含义 |
|---|---|---|
| 随机猜 | 25.0% | 四个选项等概率乱选 |
| 全选 C | 29.9% | 本数据集答案分布：A 20.4% / B 26.3% / C 29.9% / D 23.4% |

模型若落在 25%–30%，等于没读题。答案分布本身略偏 C，这是站点题库的既有偏差，
汇报时应说明：**全选 C 也能拿 29.9%，别把 30% 当"会做一点"**。

### 2.5 为什么不用 BLEU / 人工评分

答案是一个字母，没有部分正确。任何"过程分"都会引入裁判模型或人工，
既不可复现，也会把"模型会不会考试"和"模型写得好不好看"混在一起。
这一版只回答一个问题：**给定同一批题，哪个模型选对的更多。**

## 四、结果怎么展示（汇报页结构）

1. **主表：模型 × 测试方式 × 总准确率**
   列：模型 / 测试方式 / 部署方式 / 准确率 + 95%CI / 六板块宏平均 / 平均调用次数。
   开源模型与闭源 API 模型同表，用一列"是否开源"区分（对应课程附加要求"测试非开源模型"）。

2. **分板块柱状图**
   六板块 × 若干模型的分组柱状图。重点看两类差距：
   计算型板块（函数、数列）与推理型板块（解析几何、立体几何）的落差。

3. **板块 × 难度热力矩阵**
   行=板块，列=基础/中档/压轴，格内是准确率。用于回答"模型是在哪一档掉下去的"。

4. **难度曲线**
   横轴难度（基础→中档→压轴），纵轴准确率，每条线一个模型。
   理想形态是缓慢下降；断崖式下降说明模型依赖套公式。

5. **错误类型分布**
   未抽取 / 选项混淆（错在相邻选项）/ 计算错误 / 读题错误（人工抽 50 条归纳）。

6. **结论与改进**
   哪个板块最弱、哪一档最弱、是否存在"背题"迹象（对比 `fresh` 子集与老题子集的差值）。

## 五、防污染对照

数据集带 `year` 字段，按年份切三档：

| 子集 | 含义 | 用途 |
|---|---|---|
| `fresh`（2019 及以后） | 公开晚，训练语料覆盖概率低 | 与老题对比，差值≈记忆红利（本版仅 147 条，只作方向参考） |
| `2010–2018` | 中等暴露 | 过渡带 |
| `2009 及以前` | 公开十余年，最可能被记住 | 高分要打折看 |

汇报口径：**总准确率看相对排名，`fresh` 子集的准确率看真实能力**。
两者差距越大，说明"背题"成分越重。

## 六、一次评测的产物

```
results/
├── results_<tag>.jsonl   逐题记录：pred / gold / correct / 抽取方式 / 耗时 / 原始输出
├── summary_<tag>.json    全部切片指标 + 运行元信息（模型、Prompt、温度、时间）
├── summary_<tag>.md      可直接贴进汇报的结果页
├── per_item_<tag>.csv    逐题表（人工复核用）
└── matrix_<tag>.csv      板块 × 难度矩阵
```

`summary_*.json` 里 `meta` 记录了数据集路径、Prompt 模板、温度、并发、种子，
任何人拿同一份数据与同一组参数都能复现同一张表。

## 七、稳健性约定（审计后加固）

| 场景 | 处理 |
|---|---|
| 同 tag 重跑 | 未加 `--resume` 时覆盖写明细文件，避免明细与 summary 口径不一致 |
| API Key 缺失 | 启动即退出（exit 2），不会跑到最后才发现 401 |
| 网络不通 | 启动做一次 1-token 连通性探测，失败退出（exit 3），可用 `--skip-probe` 跳过 |
| 输出被截断 | `finish_reason == length` 且没有明确「答案：X」时，不认正文里的字母，记为未抽取 |
| 复核轮失败 | 回退到上一轮有效答案，不因末轮失败判 0 分 |
| 图片题 | 149 条已本地化到 `assets/`；40 条源页无图，纯文本不可解；离线评测建议 `--subset core`（3,811 条） |

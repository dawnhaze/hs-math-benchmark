# 脚本使用说明

> 适用：第三次汇报交付包 `mathbench_v3/`。三条命令链路——**采集 → 构建数据集 → 评测**，
> 每步都能单独跑，也能串起来复现。

---

## 一、环境

```bash
# Python 3.10+（本项目在 3.13 上跑通）
pip install requests beautifulsoup4 lxml PyYAML
# 本地模型另装（按需，不装不影响 API 评测）
pip install transformers torch accelerate      # hf 后端
pip install llama-cpp-python                   # llamacpp 后端
```

第二阶段遗留包 `k12crawler` 依赖 `typer / rich` 的 CLI，本交付改为直接调用流水线
（`crawler/run_crawl.py`），因此**不强制安装 typer**，少一个装不上的依赖。

---

## 三、采集

### 3.1 1010jiajiao（学科栏目，断点续爬）

```bash
cd crawler
python run_crawl.py --pages 600          # 从断点继续翻 600 页
python run_crawl.py --pages 20 --start 900   # 指定起始页
```

- 断点存在 `data/k12.sqlite3` 的 `state` 表（键 `jiajiao1010-subject:gzsx:next_page`），
  中断后重跑自动续；
- 参数在 `crawler/config/config.yaml` 的 `crawler` 段：并发、间隔、重试、空页探测；
- 产物：`data/k12.sqlite3` + `data/questions.jsonl`（追加）。

### 3.2 1010jiajiao 随机页补样（平衡板块）

```bash
python crawl_random.py --pages 1400 --workers 18
```

- 顺序爬（第 239→625 页）会把相邻上传的同类题扎堆采进来，导数只占 1.9%；
  在 26 万页里跳采，随机页的导数类题干占 8.3%；
- `data/raw/visited_pages.json` 记录已采页号，重跑自动跳过；
- 产物：`data/raw/jiajiao_random.jsonl`；
- 并发开得高（18 线程、0.06 秒间隔），站点是静态页，实测 450–500 题/分；
  若出现 403/超时，把 `--workers` 降到 8、间隔调到 0.15。

### 3.3 菁优网（试卷 → 逐题答案）

```bash
python crawl_jyeoo.py --papers 110 --workers 6 --delay 0.25 \
    --sitemap-from 1 --sitemap-to 8 --stride 21
```

- 走 sitemap 抽样：`/sj/<uuid>` 试卷页 → `/shiti/<uuid>` 详情页取答案与考点；
- 只收标题含「高中数学试卷」的卷子，其余学科整份跳过；
- 产物：`data/raw/jyeoo_raw.jsonl`。

> **限流说明**：PC 端 `/sj/`、`/shiti/` 在连续请求后会返回 403，移动端 `m.jyeoo.com`
> 同内容正常。适配器统一走移动端；若仍遇 403，把 `--delay` 调到 0.6 以上、`--workers` 降到 3。

## 四、构建数据集

```bash
python build_v3.py --target 4000
# 自定义输入输出
python build_v3.py --db data/k12.sqlite3 --jyeoo data/raw/jyeoo_raw.jsonl \
    --target 4000 --out data/benchmark_v3 --seed 42
```

### 4.1 导出团队模板格式并校验

```bash
python export_template.py      # 扁平 → 《高考题目数据集 JSON 收集规范 v1.0.0》
python validate_template.py    # 逐条校验，失败写 template_invalid.jsonl
```

产物：

| 文件 | 内容 |
|---|---|
| `benchmark_v3.jsonl` | 4,000 条评测集，字段见《数据集说明》 |
| `stats_v3.json` | 分布统计、过滤明细、难度切点 |
| `quality_report.md` | 六项质检规则的通过率与漏斗 |
| `splits.json` | core / extended / fresh / dev / test 的 id |
| `review_sample.csv` | 200 条人工抽检清单（带空列供标注） |
| `benchmark_v3.template.jsonl` | **主交付**：模板格式，一行一题 |
| `benchmark_v3.template.json` | 同内容 JSON 数组 |
| `template_validation.json` | 校验汇总（尝试/有效/失败/跳过） |
| `spec_v3.json` | 板块关键词、权重、难度与质检规则 |
| `charts/*.svg` | 汇报图：板块堆叠、年份分布、构建漏斗 |

构建是确定性的：同一个 `--seed` 与同一批原始数据，抽出来的 4,000 条完全一致。

抽样分两层：**板块间做 maximin 均分**（小板块先装满，剩余名额均分，保证极差 ≤100），
**板块内按难度分值排名切 40/40/20**。若某板块储量不足，`stats_v3.json` 里
`board_balance.pass` 会是 `false`，终端也会打 WARN——这时继续补样（`crawl_random.py`）再重建。

## 五、评测

### 5.1 先跑通链路（不需要 Key、不需要显卡）

```bash
cd eval
python evaluate.py --provider mock --tag smoke --limit 100
# 也可以直接读模板格式的数据集（脚本会自动识别字段）
python evaluate.py --dataset ../crawler/data/benchmark_v3/benchmark_v3.template.jsonl --provider mock --tag smoke
```

`mock` 后端按 id 哈希 + 难度模拟作答，用来验证并发调度、答案抽取、指标聚合、导出是否正常。
结果里 `meta.mock = true`，**不能当模型成绩引用**。

### 5.2 调 API（OpenAI 兼容：OpenAI / DeepSeek / 通义 / 智谱 / vLLM / Ollama）

```bash
export DEEPSEEK_API_KEY=sk-xxx
python evaluate.py --provider openai --model deepseek-chat \
    --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY --tag ds-chat

# 本地 vLLM 起服务后同理
python evaluate.py --provider openai --model qwen2.5-7b-instruct \
    --base-url http://127.0.0.1:8000/v1 --tag qwen-vllm

# 本地 Ollama
python evaluate.py --provider openai --model qwen2.5:7b \
    --base-url http://127.0.0.1:11434/v1 --tag qwen-ollama
```

### 5.3 本地权重（transformers / GGUF）

```bash
python evaluate.py --provider hf --model-path /models/Qwen2.5-7B-Instruct --tag qwen7b
python evaluate.py --provider llamacpp --model-path /models/qwen2.5-7b-q4_k_m.gguf --tag qwen7b-gguf
```

本地后端自动串行（`concurrency=1`），避免显存竞争。

### 5.4 常用参数

| 参数 | 作用 |
|---|---|
| `--mode normal\|deep` | 常规测试 / 深度思考测试（固定提示词） |
| `--deep-rounds N` | deep 模式总轮数（含首答），默认 2；3 表示首答 + 2 轮复核 |
| `--limit N` | 只跑前 N 题（冒烟） |
| `--subset core extended` | 只跑纯文本题 / 含图题 |
| `--board 函数 数列` | 按板块筛 |
| `--difficulty 压轴` | 按难度筛 |
| `--split dev` | 只跑 dev（调 prompt 用，别在 test 上调） |
| `--source jyeoo` | 只跑第二来源，观察单源差异 |
| `--temperature 0.7 --max-tokens 1024` | 覆盖配置 |
| `--resume` | 跳过已出结果的题，续跑；不加则覆盖旧明细（防止同 tag 混写） |
| `--api-key` | 直接给 Key（推荐 `--api-key-env`，避免进 shell 历史） |
| `--skip-probe` | 跳过启动时的连通性探测 |
| `--dry-run` | 只打印 prompt，不调模型 |

### 5.5 结果文件

```
results/
├── results_<tag>.jsonl    逐题：pred / gold / correct / 抽取方式 / 耗时 / 原始输出
├── summary_<tag>.json     全量指标（含各切片与矩阵）
├── summary_<tag>.md       可直接贴进汇报的结果页
├── per_item_<tag>.csv     逐题表（Excel 可开）
└── matrix_<tag>.csv       板块 × 难度 准确率矩阵
```

多模型汇总：

```bash
python compare.py --results results --out results/leaderboard.md
```

## 六、常见问题

**1. 采集全是乱码 / 三角形变 D**
站点是 GBK 混编，`decode_body` 已按响应头、meta、GB18030 依次尝试；`repair_mojibake`
再把 `DABC→△ABC`、`Ð→∠` 修回来。若出现 `�`，该题在质检第 3 关会被拦下。

**2. 菁优返回 403**
PC 端 WAF 限流。已切移动端；仍 403 时降低并发与频率，或隔几分钟再跑。断点不丢——
已写入的题不会重复抓。

**3. 断点续爬怎么确认**
```bash
python -c "import sqlite3;c=sqlite3.connect('data/k12.sqlite3');print(c.execute('select * from state').fetchall())"
```

**4. 没装 typer 能不能跑**
能。`run_crawl.py` 直接调用 `CrawlPipeline`，不经过 `cli.py`。

**4.5 API Key 没生效 / 401**
脚本现在会启动时校验：非本地端点缺 Key 直接退出（exit 2）；Key 无效或网络不通，连通性探测失败退出（exit 3）。
检查 `--api-key-env` 指向的环境变量是否真的 export 了。

**5. 评测卡住 / 大量超时**
把 `--concurrency` 降到 4，`timeout` 调大；端点限流时错误会记录在 `error` 字段，
不影响其它题继续跑，最后在 `error_rate` 里体现。

**6. 想让两次实验严格可比**
固定 `dataset`、`template`、`temperature=0`、`max_tokens`、同一 `--tag` 前缀；
换模型只改 `--model/--base-url`。
